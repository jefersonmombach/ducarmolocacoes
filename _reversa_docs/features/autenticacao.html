Autenticação & Segurança JWT

Segurança

Gerencia o controle de acesso, identificação e autorização de operadores e administradores do sistema via JSON Web Tokens (JWT) stateless, além de cadastro e ativação de contas.

Requisitos Funcionais Especificados 4 Requisitos
ID Requisito Prioridade Critério de Aceite
RF-AUTH-01 Autenticação por usuário e senha com emissão de JWT Must Retorna 200 OK com token assinado no body (`id_token`) e no header `Authorization: Bearer `.
RF-AUTH-02 Validação de token em requisições protegidas Must Requisições com token válido recebem autorização compatível com suas roles (`ROLE_USER`/`ROLE_ADMIN`).
RF-AUTH-03 Registro e ativação de conta Should Envia e-mail com chave de ativação; rota `/api/activate?key=...` ativa o usuário.
RF-AUTH-04 Redefinição de senha Should Endpoint `/api/account/reset-password/init` gera token temporário com validade registrada.
Regras de Negócio & Invariantes
  • Senhas devem ser armazenadas exclusivamente com hash BCrypt (60 caracteres). 🟢
  • O token JWT padrão tem validade de 24 horas (86.400s). Se `rememberMe = true`, a validade é estendida para 30 dias (2.592.000s). 🟢
  • Contas cadastradas via `/api/register` iniciam com `activated = false` até confirmação de token de ativação. 🟢
  • Usuários inativos (`activated = false`) têm o login bloqueado com `UserNotActivatedException`. 🟢
Critérios de Aceitação Formal (Gherkin)
Cenário: Autenticação bem-sucedida de operador
  Dado que existe um usuário "atendente" ativo no banco de dados com senha "senha123"
  Quando enviar uma requisição POST /api/authenticate com { "username": "atendente", "password": "senha123" }
  Então a resposta deve ter status 200 OK
  E o corpo deve conter a propriedade "id_token" preenchida
  E o cabeçalho Authorization deve conter "Bearer "

Cenário: Tentativa de login com senha incorreta
  Dado que existe um usuário "atendente" ativo no sistema
  Quando enviar uma requisição POST /api/authenticate com { "username": "atendente", "password": "senhaErrada" }
  Então a resposta deve ter status 401 Unauthorized
  E nenhum token JWT deve ser emitido

Cenário: Tentativa de login de usuário não ativado
  Dado que existe um usuário "novo_usuario" com activated = false
  Quando enviar uma requisição POST /api/authenticate com as credenciais corretas
  Então a resposta deve ter status 401 Unauthorized
  E a mensagem de erro deve indicar que a conta não foi ativada
