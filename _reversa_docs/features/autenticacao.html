Acesso e Operadores Locais

Segurança Simplificada

Modelo de segurança desktop local simplificado: substituição do complexo mecanismo stateless de tokens JWT REST por controle de operadores locais diretamente no aplicativo de balcão da loja.

Requisitos Funcionais Especificados 3 Requisitos
ID Requisito Prioridade Critério de Aceite
RF-AUT-01 Identificação do Operador Must O sistema registra o operador logado em cada contrato e alteração de locação.
RF-AUT-02 Eliminação de Tokens Expiráveis Must Operação contínua no balcão sem desconexões involuntárias ou expiração de token JWT.
RF-AUT-03 Sessão Local Segura Must Manutenção de credenciais protegidas na base local com permissões administrativas.
Regras de Negócio & Invariantes
  • Segurança por Design: Descarte de endpoints HTTP públicos, eliminando vetores de ataque remoto contra a loja física.
Critérios de Aceitação Formal (Gherkin)
Cenário: Abertura da aplicação desktop pelo operador
  Dado que o operador inicia o executável nativo ducarmolocacoes
  Quando o sistema carrega a janela principal
  Então a sessão local do operador é ativada imediatamente sem dependência de rede
